## ✅ **AWS KMS Asymmetric Key Integration for JWS/JWKS in Spring Boot**

---

### **1. Overview**

This document describes how to integrate **AWS Key Management Service (KMS)** with a **Spring Boot** application for cryptographic operations such as **signing and verifying JWS (JSON Web Signatures)** using **asymmetric RSA keys** stored securely in AWS.

You will learn how to:

* 🧩 Create an **asymmetric key pair (RSA)** in AWS KMS
* 🔑 Retrieve and convert the **public key** to **JWKS (JSON Web Key Set)** format
* ✍️ Use AWS KMS to **sign payloads** (using the private key that never leaves KMS)
* ✅ **Verify JWS tokens** locally using the retrieved public key
* 🛡️ Assume IAM roles securely (for EKS, EC2, or cross-account signing)

### **4. Create Asymmetric Key in AWS KMS**

1. Go to **AWS Console → KMS → Create Key**
2. **Key Type:** Asymmetric
3. **Key Usage:** `Sign and Verify`
4. **Key Spec:** `RSA_2048`
5. **Alias:** `alias/springboot-asymmetric-key`
6. **IAM Permissions:**

   * `kms:GetPublicKey`
   * `kms:Sign`
   * `sts:AssumeRole`
7. Note down the **Key ARN** — example:

   ```
   arn:aws:kms:us-east-1:123456789012:key/abcd1234-56ef-7890-ab12-3456cd7890ef
   ```

### **7. Code Implementation**

#### **7.1 Assume Role and Initialize KMS Client**

```java
public KmsClient getAssumedRoleKmsClient(String region, String roleArn) {
    Region awsRegion = Region.of(region);

    StsClient stsClient = StsClient.builder().region(awsRegion).build();

    StsAssumeRoleCredentialsProvider provider = StsAssumeRoleCredentialsProvider.builder()
        .stsClient(stsClient)
        .refreshRequest(b -> b.roleArn(roleArn).roleSessionName("KmsAssumeRoleSession"))
        .build();

    return KmsClient.builder()
        .region(awsRegion)
        .credentialsProvider(provider)
        .build();
}
```

---

#### **7.2 Retrieve Public Key from KMS**

```java
GetPublicKeyResponse response = kmsClient.getPublicKey(
    GetPublicKeyRequest.builder().keyId(kmsKeyId).build()
);

RSAPublicKey rsaPublicKey = (RSAPublicKey) KeyFactory.getInstance("RSA")
    .generatePublic(new X509EncodedKeySpec(response.publicKey().asByteArray()));

RSAKey jwk = new RSAKey.Builder(rsaPublicKey)
    .keyUse(KeyUse.SIGNATURE)
    .algorithm(JWSAlgorithm.RS256)
    .keyID(kmsKeyId)
    .build();

Map<String, Object> jwks = new JWKSet(jwk).toJSONObject();
```

---

#### **7.3 Sign Payload Using AWS KMS**

```java
// Create JWS header and payload
JWSHeader header = new JWSHeader.Builder(JWSAlgorithm.RS256)
    .keyID(kmsKeyId)
    .build();

String payloadJson = new JSONObject(payload).toString();
JWSObject jwsObject = new JWSObject(header, new Payload(payloadJson));

// Compute SHA-256 digest
MessageDigest md = MessageDigest.getInstance("SHA-256");
byte[] digest = md.digest(jwsObject.getSigningInput());

// Sign using AWS KMS private key
SignResponse resp = kmsClient.sign(SignRequest.builder()
    .keyId(kmsKeyId)
    .message(SdkBytes.fromByteArray(digest))
    .messageType("DIGEST")
    .signingAlgorithm("RSASSA_PKCS1_V1_5_SHA_256")
    .build());

String token = jwsObject.getSigningInput().toString() + "." +
    Base64URL.encode(resp.signature().asByteArray());
```

---

#### **7.4 Verify JWS Token**

```java
JWSObject jws = JWSObject.parse(token);
boolean verified = jws.verify(new RSASSAVerifier(jwk.toRSAPublicKey()));

if (verified) {
    System.out.println("✅ Signature verified successfully!");
}
```

### **8. REST Endpoints**

| Endpoint                  | Method | Description                                         |
| ------------------------- | ------ | --------------------------------------------------- |
| `/kms/jwks.json`          | GET    | Returns JWKS JSON containing public key             |
| `/kms/sign`               | POST   | Signs payload using AWS KMS and returns compact JWS |
| `/kms/verify`             | POST   | Verifies JWS token locally using JWKS public key    |
| `/kms/create-key/{alias}` | POST   | Dynamically creates new KMS symmetric key           |

### **10. Security and Operational Best Practices**

✅ **Key Management**

* Use aliases (e.g., `alias/app-signing-key`) to avoid hardcoding key IDs.
* Rotate keys periodically via AWS KMS policies.
* Restrict `kms:Sign` and `kms:GetPublicKey` permissions to trusted IAM roles only.

✅ **App Security**

* Always access KMS via **STS assumed role**, not permanent credentials.
* Validate all payloads before signing.
* Use HTTPS for all API requests.

✅ **Performance**

* Cache public keys (JWKS) for 10–15 minutes to reduce AWS KMS calls.
* Handle KMS throttling gracefully using exponential backoff.
